# Groove Lab · 街舞教练课程站（从零实现）

面向少儿/青少年/成人的街舞工作室站点：前台展示舞风、教练、场地、年龄分组、学员成果与试听入口；
后台 API 用 **SQLite（WAL）持久数据库**维护场地、教练、年龄分组、场次、预约、候补与少儿视频授权。

## 运行

```bash
npm install
npm start                 # http://localhost:3000
npm test                  # 18 个验收测试（含并发竞争场景）
```

演示管理令牌：`dev-admin-token`（可用环境变量 `ADMIN_TOKEN` 覆盖）。
种子数据：3 个场地、4 位教练、3 个年龄分组、4 场试听（含 2 人小班与人工候补场）、2 个已授权成果视频。
环境无 ffmpeg，演示正片为 SVG 占位素材；数据模型、门禁、转码作废流程与真实视频一致。

## 关键设计：为什么不会超额占位

选课卡上的“剩余 N”只是读取瞬间的**提示值**。真正的核对发生在学员点击确认时，
在单个 SQLite **`BEGIN IMMEDIATE` 立即写事务**内串行完成：

1. 场次仍开放，教练在职且未被移除、场地启用（临时换场/代课的可用性）；
2. 教练与场地在该时间段没有别的场次重叠（建场/改场时同样核对）；
3. `holdCount = booked + invited + pending_change` 严格小于班级容量（候补不占位）；
4. 同一学员同时占位场次不超过 `MAX_ACTIVE_HOLDS`（默认 2，候补不计入）；
5. 同场次活动占位唯一（部分唯一索引）+ 前端按钮锁定 + 幂等键，防重复点击挤满名额。

两人并发抢最后名额时，第二个事务在第一个提交后才读到最新计数：1 人 `booked`、1 人 `waitlisted`，绝不超额。

## 候补：自动递补 vs 人工邀请

- **auto 自动递补**：确认占位者取消/拒绝改期释放名额后，同一事务内把队首**仍有资格**（未超每人占位上限）的候补直接补为 `booked`。
- **manual 人工邀请**：管理员对某位候补发起邀请，邀请 24h 有效（`MANUAL_INVITE_TTL_MS`），期间**临时占用名额**；
  学员接受（再次原子核对容量/资源）、婉拒（释放名额，不自动递补）、超时（惰性检查 + 定时清扫，置 `expired`）。
  管理员可**撤下邀请**（退回候补、空位保留给他人），此时学员再点接受会得到 409。
- **改期/换场/代课**：编辑教练、场地或时间会让 `schedule_version+1`：
  已确认学员进入 `pending_change`（名额保留），待接受的邀请退回候补；学员确认时按新安排复核资源，拒绝则释放并按模式递补。
  容量收缩不得低于既有确认占位数。

## 少儿成果视频：独立授权、可到期、撤销要“真撤下”

- 每个视频需**独立授予监护人授权**（可设到期时间），授权轮次 `consent_epoch` 每授权一次 +1。
- 公开面（成果墙、封面/片段资产接口、分享 token）只在 `published=1 且 consent=active` 时可用；
  到期经惰性评估 + 定时清扫切断，**不是只从列表隐藏**：资产接口 410/403，分享记录置 `revoked`。
- **撤销（终态，不可重新授权同一视频）**在一个事务内完成访问切断：
  ① `revoked` 停播；② 全部有效分享作废；③ queued/processing 转码任务作废；
  ④ 封面与片段标记移除；⑤ 物理删除服务端源/封面/片段/输出文件。管理页展示四阶段撤下进度时间戳。
- **迟到的转码任务**：任务完成时校验视频状态与 `consent_epoch`，撤销/失效/轮次不匹配一律 `rejected` 且不产出文件。
- **外部副本**：已被下载或转发的文件无法远程抹除——系统只关闭线上入口并删除服务端文件，UI 与撤下结果中如实说明，需联系持有人手动删除。

## 验收测试（`node --test tests/`）

1. 两人并发争最后名额：1 确认 1 候补，严格不超额；重复点击幂等；每人占位上限。
2. 临时换场：冲突场地被事务拒绝，换到空闲场地后学员进入“待确认改期”且名额保留。
3. 教练代课：冲突教练被拒，换到空闲教练生效并待确认。
4. 候补邀请与取消竞争：自动递补、人工邀请 24h 有效期、撤下邀请后接受失败、超时 410。
5. 旧视频转码任务迟到：撤销/授权轮次变更后完成均作废且无产物；撤销联动封面、片段、分享、物理文件。
